BEFORE YOU START

Four tools. Different jobs.

AI assistant
Explains things and helps write code. A chat-only assistant gives you text to copy. An assistant with computer tools may also edit files or run commands, with your permission.
Browser
Opens GitHub and shows your website.
Text editor
Shows the code inside a file. You’ll use one in step 5.
GitHub
Stores your project and its history. GitHub Pages turns suitable files into a public website.

Have an email address you can access and your preferred AI assistant ready. The first four lessons need only your browser. The local route later uses GitHub Desktop on Windows or macOS.

Copy this into your AI chat
I have never coded. Help me create and publish a simple HTML website on GitHub Pages. Explain why each step matters before telling me what to click. Give me one step at a time and wait for my result. Tell me clearly when I need to do something myself.
LESSON 01 · IN YOUR BROWSER

Create your GitHub account

Why: your account is where your projects will belong.

  1. Open GitHub signup.
  2. Follow the prompts to choose an available username and enter your account details. Use an email address you can verify.
  3. Complete the verification steps and review the terms before creating your account. Enter passwords and verification codes on GitHub, not in an AI chat.
You’re ready when…You’re signed in and can open your profile. Keep your username handy: it will appear in your website address.
What happened to meThe assistant’s browser hit a verification screen. Opening GitHub in my regular browser let me continue. It was a browser hurdle, not a coding mistake.

Already have an account? Use it and move to lesson 2.

LESSON 02 · IN YOUR BROWSER

Give your project a home

A repository is a project folder with a history of changes. We’ll call this one my-first-website.

  1. Open Create a new repository. Make sure your account is the owner.
  2. Enter my-first-website as its name. If you already used that name, choose another and substitute it throughout this guide.
  3. Choose Public for this exercise. Your uploaded files will be visible to everyone; use only content you mean to share.
  4. Enable Add a README, then create the repository.
  5. Open README.md and select the pencil/edit control. Replace its contents with the introduction below.
# My First Website

I’m learning to create a website with AI assistance.
This project records my first steps with GitHub.

Select Commit changes…, use Write my project introduction as the message, and confirm. Choose the existing main branch if asked. A commit records a version with a note about what changed.

You’re ready when…Your introduction appears in the README on the repository page.
“How do I get the repository link?”Return to the repository’s main page and copy your browser’s address. It looks like https://github.com/YOUR-USERNAME/my-first-website. Replace YOUR-USERNAME with your actual username. On Windows, Ctrl + L selects the address and Ctrl + C copies it; on a Mac use Command + L and Command + C.
LESSON 03 · AI CHAT + YOUR BROWSER

Create your first webpage

HTML describes a page’s content. CSS describes how it looks. Start with one file called index.html, the homepage.

Ask any AI assistant
Create a complete beginner-friendly index.html for a small personal website. Put the CSS inside the file. Use no external libraries, images, or build tools. Include a heading and a short list about what I am learning. Explain which text I can safely change. Return the complete file, not fragments.

Or use this working starter:

Show the complete starter code
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>My First Website</title>
  <style>
    body { max-width: 700px; margin: 40px auto; padding: 24px;
      font: 18px/1.7 system-ui; background: #f5f7fb; color: #18243a; }
    h1 { color: #3758c8; }
  </style>
</head>
<body>
  <h1>My first website</h1>
  <p>I am learning to build with AI.</p>
  <ul>
    <li>Create a GitHub account.</li>
    <li>Publish a webpage.</li>
  </ul>
</body>
</html>
  1. Return to your repository’s Code tab. Select Add file → Create new file.
  2. Name it exactly index.html, all lowercase, at the top level of the repository.
  3. Paste the HTML code. If copying from an AI answer, leave out the triple backticks and any explanatory text around the code.
  4. Commit the file with the message Add my first webpage.
You’re ready when…The Code tab lists both README.md and index.html. Seeing code on GitHub is normal—we haven’t published the page yet.
LESSON 04 · IN YOUR BROWSER

Put your website online

Why: storing code and publishing a website are different things. GitHub Pages hosts this simple HTML page.

  1. In your repository, open Settings → Pages.
  2. In Build and deployment, choose Deploy from a branch as the source.
  3. Select main and /(root), then save. Root means the top-level folder containing index.html.
  4. Open the repository’s Actions tab. Wait for the Pages deployment to succeed. Return to Pages settings for the published link.
  5. Open that link and check your heading. The website is public.

Your address normally looks like https://YOUR-USERNAME.github.io/my-first-website/.

You’re ready when…You see your designed webpage at the github.io address, rather than a list of files.
My first visit showed “404”The deployment had just finished and my tab still showed the old error. Refreshing fixed it. A 404 isn’t always a waiting issue: if it persists, check the deployment result, URL, filename and publishing folder.
Two links, two purposes

github.com/YOUR-USERNAME/my-first-website is the repository: code and history.

YOUR-USERNAME.github.io/my-first-website/ is the website: the published result.

LESSON 05 · ON YOUR COMPUTER

Make a small local change

Why do this? You can keep editing on GitHub, but a local copy lets you work in an editor and preview before uploading. Clone means download a repository with its history.

Manual route: GitHub Desktop

  1. Install GitHub Desktop for Windows or macOS. Sign in to your GitHub account and follow its Git identity setup. Use your GitHub-provided no-reply email if you want to keep your personal email out of public commits.
  2. Choose File → Clone repository. Select your repository, or use the URL tab and paste its repository link.
  3. Choose a local folder you can find again, then click Clone. If you already cloned this repository, open that copy instead; use Fetch origin and Pull origin if offered before editing.
  4. Open that folder in File Explorer or Finder. Open index.html with a plain-text/code editor. Windows users can right-click → Open with → Notepad. On macOS, use a code editor such as Visual Studio Code.
  5. Above </body>, add the paragraph below. Save with Ctrl + S on Windows or Command + S on macOS. Keep the filename index.html, not index.html.txt.
<p>I made this change on my own computer!</p>

Open the same file in your browser and refresh to preview. A file:/// address is your local preview. Your github.io page has not changed yet.

“I see the page rendered”Double-clicking HTML usually opens a webpage. That’s useful for previewing, but you need an editor to change its code. The same file has two views.
If your AI assistant can work with local files
Clone my repository into a local project folder, or open the existing clone if there is one. Explain where it is. Help me add a paragraph to index.html and preview it locally. Show me the exact change before making a commit. Do not overwrite unrelated edits.

Give it your own repository link. If the assistant cannot access files, follow the manual steps above. On Linux, GitHub Desktop’s official app is unavailable; ask your assistant for Git installation and clone steps specific to your distribution.

You’re ready when…Your local browser preview contains the new paragraph, and GitHub Desktop lists index.html under Changes.

LESSON 06 · GITHUB DESKTOP + YOUR BROWSER

Save a version. Send it. See it live.

Save → Commit → Push → Publish

Saving writes the file on your computer. Committing records a version locally. Pushing sends that version to GitHub. Your configured Pages deployment then publishes it.

  1. In GitHub Desktop, select your repository and confirm the current branch is main for this exercise.
  2. Under Changes, select index.html. Read the difference: additions and removals should match your intended edit. Keep only the intended files checked.
  3. In the summary field, enter Add my first local update. Click Commit to main.
  4. Click Push origin. If asked to sign in or authorize, complete the prompt on GitHub for the tool you’re using. If asked to pull first, fetch/pull the remote changes; ask for help if a conflict appears.
  5. Check your repository online for the new commit. Wait for its Pages deployment in Actions to succeed, then refresh your live website.
If your AI assistant can run Git
Review my saved changes and explain what will be included. Commit only my intended website edit with a clear message, then push it to my GitHub repository. Use my existing Git identity; if it is missing, help me configure it. Tell me whether the push succeeded and how to check the Pages deployment.

A chat-only assistant cannot push on your behalf. Use GitHub Desktop instead. If a tool starts device sign-in, use only the fresh code from your current session and review the requested access.

You’ve done it when…The new paragraph appears on your public website. You’ve completed the whole cycle—and can repeat it for the next change.
What we learned by checking the editOnce, the only saved change was a lowercase letter. That was intentional. Checking the difference before committing made sure the assistant understood what I actually wanted.

KEEP THIS HANDY

A small vocabulary, in plain English

Repository
Your project files and their recorded history.
README
The project’s introduction, usually written in Markdown.
Branch
A line of development. This exercise uses the default branch, main.
Clone
Make a local copy of a repository, including history.
Commit
Record a version of selected changes with a message.
Push
Upload local commits to the remote repository.
Pull
Bring remote changes into your local branch.
Deployment
The process that publishes your files as the live website.
Terminal
A place to type commands. An AI assistant is a separate tool that may be able to run those commands for you.
WHEN SOMETHING DOESN’T MATCH

Check where you are first

I saved, but the website didn’t change

If you edited locally, saving is only the first step. Check for the change in GitHub Desktop, commit it, then push. Confirm the deployment succeeded and refresh the live URL. If GitHub Desktop shows no change, confirm you saved the file inside the cloned folder.

My website still says 404

Check Settings → Pages for the actual site link and source branch/folder. Confirm index.html is in that folder with exactly that capitalization. Look in Actions for a failed or pending deployment. After success, refresh. If the error remains, share the public URL and the deployment error with your assistant.

I can see the webpage, but can’t edit it

The browser renders HTML. Open the same local file with a plain-text editor to change it. The browser’s address tells you whether it is a local file or the live website.

GitHub asks me to sign in again

Being signed in to your browser does not automatically sign in GitHub Desktop or your AI’s Git tool. Complete that tool’s sign-in flow on GitHub. Keep passwords, tokens and verification codes out of your tutorial and AI chat.

My AI says it changed something, but I can’t find it

Ask which exact file it edited and whether the change was saved, committed and pushed. Compare the file in your local folder with the repository online. A proposed code snippet in chat is not automatically a saved file.

A useful help prompt
I am on lesson [number]. I expected [result], but I see [actual result]. I am using [browser/editor/GitHub Desktop] on [Windows/macOS/Linux]. Explain the likely cause in plain English and give me one check at a time. Here is the error text, with private information removed: [text].
